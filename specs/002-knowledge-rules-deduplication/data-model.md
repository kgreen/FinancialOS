# Data Model: Knowledge, Rules & Deduplication

## Design Principles

- Raw evidence and immutable record facts are never overwritten.
- All classification/normalization/duplicate outputs are layered decisions.
- Every automated or human decision emits append-only provenance.

## Entities

### ClassificationRule

Deterministic rule used to assign merchant/category outcomes.

**Fields**
- Id (Guid)
- Name (string, unique)
- Status (`Active` | `Inactive`)
- Priority (int, higher first)
- Scope (`Global` | `Account` | `Institution`)
- ConditionJson (structured deterministic match expression)
- TargetMerchantId (Guid?, canonical merchant)
- TargetCategoryId (Guid?, category)
- EffectiveFromUtc (DateTimeOffset)
- EffectiveToUtc (DateTimeOffset?)
- CreatedAtUtc (DateTimeOffset)
- UpdatedAtUtc (DateTimeOffset)

**Validation**
- Name required and unique.
- Active rules must have at least one target outcome (merchant or category).
- Priority required; ties resolved by deterministic secondary ordering.

### CanonicalMerchant

Normalized merchant identity used for reporting consistency.

**Fields**
- Id (Guid)
- DisplayName (string)
- NormalizedKey (string, unique)
- DefaultCategoryId (Guid?)
- IsActive (bool)
- CreatedAtUtc (DateTimeOffset)

### MerchantAliasMap

Maps raw merchant variants to canonical merchant.

**Fields**
- Id (Guid)
- CanonicalMerchantId (Guid)
- AliasRawText (string)
- AliasNormalizedText (string)
- MatchStrategy (`Exact` | `Contains` | `TokenSet`)
- ConfidenceWeight (decimal 0..1)
- IsActive (bool)
- CreatedAtUtc (DateTimeOffset)

**Validation**
- AliasNormalizedText required.
- ConfidenceWeight in range [0, 1].

### NormalizationDecision

Record-level result from normalization + deterministic rules.

**Fields**
- Id (Guid)
- FinancialRecordId (Guid)
- CanonicalMerchantId (Guid?)
- CategoryId (Guid?)
- RuleId (Guid?)
- Confidence (decimal 0..1)
- Status (`Resolved` | `Unresolved` | `Overridden`)
- ReasonCodes (string collection / JSON)
- CreatedAtUtc (DateTimeOffset)
- SupersededByDecisionId (Guid?)  *(link only; original row remains immutable)*

### DuplicateCandidate

Potential duplicate pair/group generated by heuristic evaluation.

**Fields**
- Id (Guid)
- CandidateGroupKey (string)
- RecordId (Guid)
- MatchedRecordId (Guid)
- Confidence (decimal 0..1)
- Status (`PendingReview` | `ConfirmedDuplicate` | `Dismissed`)
- ReasonCodes (string collection / JSON)
- SignalSnapshotJson (JSON: amount/date/account/text similarity values)
- EvaluatedAtUtc (DateTimeOffset)
- ReviewedByUserId (string?)
- ReviewedAtUtc (DateTimeOffset?)

### ProvenanceEntry (Append-Only)

Immutable audit trail for system and human actions.

**Fields**
- Id (Guid)
- FinancialRecordId (Guid)
- StepType (`Normalization` | `RuleEvaluation` | `DuplicateDetection` | `DuplicateReview` | `ManualOverride`)
- StepSequence (long, monotonic per record pipeline run)
- Source (`system` | `user`)
- SourceReference (rule id, alias id, endpoint/action id)
- Confidence (decimal? 0..1)
- DecisionSummary (string)
- ReasonCodes (string collection / JSON)
- ActorId (string?)  *(required for user actions)*
- CorrelationId (Guid) *(pipeline run id)*
- CreatedAtUtc (DateTimeOffset)

**Validation**
- Never updated or deleted.
- `Source=user` requires ActorId.

## Relationships

- `CanonicalMerchant` 1 → * `MerchantAliasMap`
- `FinancialRecord` 1 → * `NormalizationDecision`
- `FinancialRecord` 1 → * `DuplicateCandidate` (as `RecordId` or `MatchedRecordId`)
- `FinancialRecord` 1 → * `ProvenanceEntry`
- `ClassificationRule` 1 → * `NormalizationDecision` (optional linkage)
- `DuplicateCandidate` actions emit `ProvenanceEntry` rows

## State Transitions

### NormalizationDecision

`Unresolved` → `Resolved` (system finds confident match)  
`Resolved` → `Overridden` (human/manual reassignment)  
`Unresolved` → `Overridden` (human direct assignment)

### DuplicateCandidate

`PendingReview` → `ConfirmedDuplicate` (human confirm)  
`PendingReview` → `Dismissed` (human dismiss)  
`ConfirmedDuplicate` → `Dismissed` (reversal via explicit override event with new provenance row)

## Deterministic Pipeline Order (Record Processing)

1. Normalize merchant text and lookup aliases.
2. Evaluate active rules in deterministic order.
3. Persist single normalization/classification decision.
4. Evaluate duplicate heuristics against candidate set.
5. Emit provenance entries for each step and score.
6. Await optional human review actions for duplicate decisions.
