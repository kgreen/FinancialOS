# FinancialOS Constitution

## Core Principles

### I. Truth Before Convenience
Every feature must preserve immutable evidence and treat corrections as layered interpretations rather than overwriting the original source.

### II. Facts Are Immutable
Observable financial reality such as amounts, dates, raw text, and source artifacts must remain unchanged; only interpretation and classification evolve.

### III. Explainability Is Required
Every categorization, insight, or recommendation must expose its confidence score, provenance, and underlying rules so users can inspect and challenge it.

### IV. Humans Contain Authority
System decisions are advisory only. Users retain absolute control over financial truth and action.

### V. Knowledge Before Intelligence
Core correctness must rely on deterministic logic, explicit rules, and auditable data structures before AI-assisted interpretation is introduced.

### VI. Modular & API-First
Domain truth belongs in the core engine, while UI applications and integrations remain consumers of stable contracts.

## Architectural Constraints

- The platform must support local-first ingestion and later server deployment without changing the domain model.
- The core domain must remain independent of UI and infrastructure details.
- Evidence, records, accounts, merchants, categories, and rules must be modeled explicitly and traceably.
- The API must be the primary integration boundary for desktop, web, and mobile clients.

## Governance

All implementation work must remain consistent with the principles above. Any plan that violates the constitution must document the deviation and justify why the tradeoff is necessary.
